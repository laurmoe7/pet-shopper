# Fumufumu (repo: pet-shopper; the pet is called Fumu)

A grocery list with a tamagotchi-like pet that "eats" items as you check them off and gets happy. It also has a to-do list mode. Owner: Lauren (GitHub laurmoe7), based in Europe. Private project. See `README.md` for the feature list and `docs/` for research and the pet/core-loop design.

## Product decisions

- **Names (decided build 252):** the app is **Fumufumu** (ふむふむ: "hmm, I see", said while nodding) and the mascot is **Fumu**, a pigeon (head bobs, eats anything). New players start as the pigeon (species `birdie`, skin `pigeon`, named Fumu; these are the `petProfile` defaults, older saves keep their own species; old saves named Nibble become Fumu), and the species list starts bird, cat, dog, mochi (`SPECIES` in `app-petsheet.js`); the mochi is shown as "Mochi". Internal names that must NOT change, because saved data and installs depend on them: the `nibble.v1`, `nibble.*` and `nibble-*` storage keys, the `nibble-vNN` cache names, `window.nibbleDesktop`, `NIBBLE_URL`, the installer id `com.laurmoe.nibble` and the `nibble-desktop` package name. The pigeon skin `pigeon` is the new design; the earlier one is `oldpigeon` ("Pigeon (old)"). A pet "nods" (`nod` in `SQUISH`) when you add an item, with a "fumu fumu~" line now and then.
- Free, usable, no ads. Monetization later via paid pet customization (the dressing room tests that idea; no payments yet).
- Deals/price data are dropped for now (store data is US-centric and not useful in Europe). Research is parked in `docs/research/competitors-and-deal-data.md`.
- Each person gets their own pet; only lists would be shared (not a household pet). All pet data stays in one object (`state.pet`, via `PetLogic.petProfile`) so it can sync per person. Keep it that way. The desktop companion and account sync exist (see `docs/design/desktop-companion-and-sync.md`; no AI chat, desktop awareness never reads window titles). Awareness has two levels the player picks in the desktop settings (Privacy: 1 more privacy, 2 normal): see `desktop/privacy.js`; every new thing that notices what the player does must be gated by it. Level 2 means the front program's file name (matched in the shell against `desktop/programs.js`, which is the only thing that may name a program to the page) and window positions, never titles: do not describe it as reading titles, and never send the page a program name that is not on the list (`programs.describe`). The page reacts in `app-desktop.js` (`onProgram`, `mayRemark`, `quietNow`; remarks run at the rate chosen in settings, `chatRate`, one for the usual case and one for games/full-screen, `inFull`; `moveOk` is the stand-still choice; per-game lines go in `GAME_LINES`). How much he talks on his own is `chatterRate` (`app-pet.js`; `applyChatter` in `app-desktop.js` picks the usual or the full-screen choice) and `idleQuiet` mutes `say` for a silent idle move; the stable (friends') build also shows update checking and restart in the right-click menu and the settings window, with `updateState` from `main.js`.
- No known app combines a list with a pet. Real rivals are shared-list apps (AnyList, Bring!, OurGroceries, Listonic); Finch, Otto and Habbie are pet habit apps.

## How the code is organised

Plain web app, no build step, no dependencies. `npm test` runs Node's built-in test runner on `tests/`, which load the same scripts the browser uses (the `app*.js` page scripts are only checked to parse, in `tests/syntax.test.js`).

- `index.html`, `styles.css`: UI. Bottom sheets are capped by `--sheet-h` (and `--sheet-h-s`) so Fumu stays in view above them. The look is cardboard (kraft board, taped paper labels, sticker buttons) with light and dark modes; its rules are at the end of `styles.css` under `html:root`. Fumu is an inline SVG animated with CSS. The pet buttons live in the `.dock` bottom bar (Pet, Room, Shop (placeholder, greyed out), Calendar, Profile; sticker colours are set by button id).
- `app*.js`: the UI code, split by topic. Plain scripts sharing one scope (no modules), loaded in the order in `index.html`; top-level code can only use things from files loaded before it. Read only the file you need:
  - `app.js` (first): `BUILD`, saved state, helpers, page elements, list rendering.
  - `app-pet.js`: faces, speech, flying food, crumbs. `app-actions.js`: sound and haptics, eating queue, list actions, emoji picker.
  - `app-petsheet.js`: the pet's name, species and skin panel. `app-dress.js`: the Pet button's page, the dressing room: a stage on top, then tabs (`#dressTabs`: a row of six icon tabs, Pet, Hats, Clothes, Face (glasses and mouth things), Neck, Feet, whose icons are listed in `TAB_ICONS` in `tools/copy-emoji.js`; it always opens on Pet, whose panel holds the name, species, skin and personality; only the panel under the tabs scrolls; the stage rebuilds when the species or skin changes via `buildDressView`) (its stage is the `.dress-fx` SVG in `index.html`: podium, lights that sway, curtains, slowly pulsing sparkles, nothing moves about); the preview pet does little dances and poses every few seconds (`DRESS_MOVES`, the same CSS classes as the main pet), waiting while you try things on, and now and then poses for a photo (`PHOTO_MOVE`: `#dressFlash` and the `shutter` sound; also sometimes after putting an outfit on). The flash is a soft warm glow that eases in and out, at most one every 3.5 seconds, kept gentle for safety: keep it that way. `app-closet.js`: the closet, outfits saved by name in `pet.closet` (`L.saveOutfit`, `parseCloset`; up to `CLOSET_MAX`), opened by `#closetBtn` in the corner of the dressing room's stage; its sheet (`#closetSheet`) is opened with `show()` rather than `openDialog`, which would close the dressing room under it. `app-room.js`: room furniture. `app-goals.js`: goals and unlocks.
  - `app-recipe.js` (with `recipe.js`, the `Recipe` parser, and `worker/recipe-proxy.js`, the Cloudflare helper that fetches pages): Recipe sheet; the pet searches with the glass while it is open. `app-shoot.js` (photoshoot over the dressing room: backgrounds, poses, frames, camera, drag/pinch/twist) and `app-photo.js` (the Photo button: draws the picture on a canvas for Share/Save). `app-select.js`: round drop-down menus over real `<select>`s.
  - `app-todo.js`: the to-do list. `app-calendar.js`, `app-stamps.js`: its Calendar and Stamp book sheets. `app-events.js`: adding items, taps, long-presses. `app-voice.js`: adding by voice. `app-personality.js`: personalities and suggestions.
  - `app-favourites.js`: Top 10 sheet. `app-petting.js`: stroking for a purr. `app-treats.js`: wishes. Now and then (`scheduleWish`) Fumu asks for a snack: a thought cloud `#wish` with the food shows by his head, and tapping it feeds him (`L.nextWish` picks a treat not fed yet; at most 3 a day, each once; they count for goals and tastes like shopping, never the Top 10). The cloud goes away by itself, nothing is lost by ignoring it. There is no Treats menu any more; the bottom bar has four buttons.
  - `bonuses.js` (plain data and pure functions, like `decor.js`): the daily gift boxes' calendar: `PRIZES` (placeholders), `BOXES`, `DAYS` (holidays and the birthday; add a line to add a day). `app-gift.js`: the gift box on the stage and its sheet (`pet.gifts`, `pet.prizes`; dev tools to pretend a special day). `app-profile.js`: Profile (`state.player`: name and birthday, the Profile button at the end of the dock on both lists; its sheet also holds the buttons that open the Top 10 and the Stamp book).

Awareness (level 1 or 2, `desktop/privacy.js`) gates everything that notices what the player does; he never reads window titles; program names come only from `desktop/programs.js`.

The whole app always uses the Classic look (no `al-*` class), which follows its own Light or Dark appearance. Styles are at the end of `styles.css`.
  - Reminder and alert cards: swiping (drag, or sweeping the pointer while the mouse passes through him in a game) is left = Done / copy, up or down = In 10 min, right = put away (`sweepAt` in `app-desktop.js`, the drag code in `app-send.js`). Ctrl+Alt+G (`grab`) swaps pass-through and solid in games. The ring menu opens with a double click on him (`app-ring.js`).
  - The toy and the bell can fly over the whole screen in a second transparent window (`toyWin`); the page moves it with `toyAt`.
- `logic.js` (`PetLogic`): rules with no page code (item order, mood, saved state, achievements, unlocks, favourites, voice lines, `OUTFIT_SLOTS`, `BIRDS`, dev helpers). Keep logic here so it is testable.
- `wardrobe.js`: dressing-room items as SVG. Several items can be worn in one slot: `outfit[slot]` is their ids joined by commas (or `none`); use `L.wornIds`/`L.toggleWorn` (shoes are one pair at a time), and `dressUp` draws them all (clothes attributes like `data-clothes` come from the last one). Glasses (`face`) and mouth things share one stack, drawn in the order they were put on, first at the bottom (`outfit.order`, `L.faceStack`, the `.outfit-faces` layer holding a `.outfit-face` or `.outfit-mouth` wrapper per item). Slots are `hat`, `body`, `face`, `mouth`, `neck`, `feet` (`PetLogic.OUTFIT_SLOTS`), each with its own layer (`.outfit-neck` sits under the face, moved to `.outfit-neck-over` above clothes when clothes are worn). A hood and a hat take each other off. Renamed or removed items are mapped in `parseOutfit` (`logic.js`). Items have hover `lines`; a `snug` flag hides the hair twist/tuft. Add cosmetics here.
- `achievements.js`: goals and daily caps (add goals here). `personalities.js`: personalities, tastes, `voice` (Foodie is free; others are earned via `pet.tastes`; a line part is at most 34 characters and no line repeats across personalities; the icon must be an emoji that exists in `emoji/` (a test checks; `tools/copy-emoji.js` copies the personalities' icons too, so run it after changing one); the Chef's id stays `chef`, shown as Grumpy Chef). `decor.js`: draggable room furniture in `pet.room` (the rug is drawn first). `skins.js`: skins. `tasks.js`: to-do emoji. `sounds.js`: Web Audio sounds with random pitch and variants.

Full notes: `docs/design/sketchpad-notes.md`. In short: she draws vector lines over a still copy of the pet, a stage, a toy or the room, and uploads `drawings/<kind>-<mode>-<time>.svg` (plus `.strokes.json`, and `.item.js` for wardrobe items) to the **`drawings` branch** with a token kept in her browser. When she says she uploaded something: read it with `get_file_contents` on `drawings/` at ref `drawings`, redraw it cleanly as game-style SVG (not the raw strokes) and compare it over the pet; for an item, check the `.item.js` entry, add real hover lines and paste it into `wardrobe.js`. Pet drawing coordinates (160 x 150) are the same as `wardrobe.js` and `index.html`. Uploads only appear for her (`?owner=1`).

### Species and skins, to-do list, bedtime

Details are in `docs/design/pet-todo-bedtime-notes.md`: read it before touching a species or skin, the to-do list or clipboard, or bedtime. Rules to keep in mind:
- Species: birdie (the pigeon is the mascot), cat, dog (id `puppy`), mochi, pig, bunny, cow, hamster, mouse, monkey, dragon, frog, hedgehog, axolotl (`app-petsheet.js`; parts in `index.html` with `data-sp`). Prefer a skin over a new species when the change is mostly colour. Birds (`PetLogic.BIRDS`) get `.beaked` and no mouth; a beak never changes size. Eye parts move with the CSS `translate` property, never `transform`. Each foot is its own group (`.foot-l`/`.foot-r`).
- The list on show is always `state.items`; the other list waits in `state.stash` (`state.mode`, `isTodo()`). Ticking a task runs `doTask`, not `eat`; nothing in the to-do list counts for goals, tastes, trips or the Top 10.
- Night alone does not make him sleep: lamp off plus tucking in does (`fallAsleep`). Bedtime starts fresh whenever it begins, ends or he wakes while the app is open.

### Features

- **Resting mood**: `PetLogic.restingMood` is the list mood, or asleep once put to bed tonight (`pet.dozing` holds that night; checking an item off clears it in `toggle`). `refreshBedtime` drops a left-over `dozing` unless a bedtime is showing or the app opens at a real night. Use `L.mood` for list-only checks such as "all done". Options (gear) are saved in `state.settings`, separate from the pet.
- **Walking** (`walkTo`/`walkPath` in `app-idle.js`): slides `#pet` with the CSS `translate` property (`--walk-x` on `.stage`, so the bubble follows). `walkBounds` keeps it from hiding behind the receipt or bag; eating and petting stop a walk; it returns to its cushion at bedtime. It only wanders when nothing is left to buy (`mayWander`); otherwise `walkHome` brings it back to the middle.
- **Backgrounds** (`BACKDROPS` in `app-backdrop.js`): SVG 400 x 160, cut at the sides on narrow screens, picked in the Room sheet (under the furniture) and kept on the device. Each `draw(night)` returns a day or night version (night 10 pm to 7 am via `petNow`, so the dev day/night switch works).
- **Toy** (`app-toy.js`): a ball on the floor (yarn for cats, tennis ball for dogs). Tap it and it bounces away and the pet chases it (`walkTo`, `walkWide`): dogs and birds fetch it back, cats bat it, the frog snatches it with its tongue (`tongueGrab`, the `#frogTongue` strip); a cat never catches a thrown toy in the air, it waits for it to land and then hunts it (`fling` skips `caught` for 'bat'), the rest pounce and hug it. It can be dragged and thrown (`fling`, with gravity and bounces; the pet catches it or fetches it). Only a game; nothing counts for goals. Hidden at bedtime. Its default place is on the right.
- **Voice** (`app-voice.js`, `L.splitSpoken`): the mic button `#micBtn` listens once, shows the words in the box, then adds each thing said (the shopping list splits on commas and "and"/"en"; the to-do list only on commas and "then"). All speech goes through the `Voice` object (`supported`, `listen`), which uses the browser's SpeechRecognition: for the store app, swap that one object for the phone's native recognition. Language is Auto, English or Nederlands (Options, kept on the device). The manifest shortcut "Add by voice" opens `./?voice=1`, which starts listening; if the browser refuses without a tap, the mic pulses and Fumu says to tap it.
- **Aisles** (`L.AISLES`, `aisleOf`, `groupByAisle`, `aisleNodes` in `app.js`): the shopping list is shown grouped under small labels (fruit & veg, bakery, meat & fish, dairy & eggs, pantry, drinks, treats, household, health, other) in shop-walking order. It is display only: the list's own order is untouched. An item's aisle comes from its emoji's food category (beans, nuts and seeds count as pantry). Option `aisles` (on by default) turns it off.
- **Options**: `time24` (14:30 or 2:30 PM), quiet mode, vibration, goal toasts, fair-play tips, appearance, voice language; the Developer tools sheet lives in Options.

- **The desktop pet's five scenes** (`L.deskScene`, `petScene()` in `app-night.js`, also `html[data-scene]`): `day`, `day-clip` (daytime on the to-do list: the clipboard in his left hand), `night-bed` (his bed is out; asleep or tucked; the toy and clipboard are put away), `night-drowsy` (up at night, e.g. from using the shopping list, or woken by the bell) and `night-drowsy-clip` (the same on the to-do list). Every new desktop animation or interaction must work in all five: check the clipboard hand (use the right hand for anything held when the clipboard is out: wand, toy), that nothing wakes or startles him in `night-bed` (alerts and reminders only show their card there), and that bed-only things (night play in `app-night.js`, the bed turning when thrown) apply only while he lies in his bed (`inBed()`). In the small window at night, in bed, the toy is replaced by a bell (`.bell`): shake it (the first ring stirs him, the next wakes him up drowsy until morning, `bellAwake()`), or throw it and it breaks and he goes back to bed (a new one turns up a few seconds later).

## Lessons learned

- Speed: every row on the page costs frame time all the time (the pet's animations make the page redraw constantly), so the Bought list only draws its latest `DONE_SHOWN` rows (`app.js`). Don't add things that grow without limit to the page; cap what is drawn. A leak check (nodes, listeners, heap over many actions) was clean in build 237. Measure with Playwright: `Performance.getMetrics` (TaskDuration, LayoutCount) and a trace (`devtools.timeline`: Layerize, UpdateLayoutTree). `contain: layout` on `.stage` would help but breaks its fixed-position bubble.

- There are no scroll bars anywhere (sheets and the page): she dislikes them. `app-fade.js` fades the bottom edge of a scrolling menu (`.fade-b`, listed in `FADE_SELECTORS`) and of the page (`.page-fade`) while there is more to see; add any new scrolling menu to that list.
