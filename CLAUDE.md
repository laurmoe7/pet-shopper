# Fumufumu (repo: pet-shopper; the pet is called Fumu)

A grocery list with a tamagotchi-like pet that "eats" items as you check them off and gets happy. It also has a to-do list mode. Owner: Lauren (GitHub laurmoe7), based in Europe. Private project. See `README.md` for the feature list and `docs/` for research and the pet/core-loop design.

## How to work with Lauren

- She wants honest, unflattering feedback. Don't flatter; say when something looks bad or is a weak idea.
- Priority is cute and appealing. Style is kawaii, inspired by Chiikawa but original (don't copy characters). Keep all pet species.
- She tests on her phone (Chrome) and reports by build number (shown in Options, `BUILD` in `app.js`). Always bump the build when you change app files.
- Work on the session branch and publish each build to her preview artifact. Changes go live only when she says "big push": run `npm test`, then push to `main` (no pull request); the Pages workflow tests and deploys.
- **Stable channel** (for people she shares the Windows app with; see `desktop/README.md`, "Channels"): `main` is dev and moves with every big push. Only when she says "promote" (or "push to stable"): run `npm test`, then `git push origin main:stable` (never push to `stable` otherwise, never force). The `stable` branch is deployed under `/stable/` by `pages.yml`, and `desktop-stable.yml` builds the stable installer (version `1.0.N`, a `stable` pre-release, `fumuChannel` in package.json set by the workflow only; `desktop/channel.js` picks the page). Never mark the `stable` release as the latest one: dev installs follow the latest release.
- Add to `CHANGELOG.md` for each build: a heading per build and one short line per change (a few words, no explanations or technical detail).
- She wants people to use the list legitimately, not game it for unlocks (hence the fair-play rules).
- Nothing requires an unlock for now: `FreeUnlocks.all` in `achievements.js` opens every species, skin, hat and personality. New things should not need unlocks either; goals still count progress, and setting `all` to false brings unlocking back (the rules and tests are kept).
- Keep files focused. Put new code in the `app-*.js` file for its topic, and start a new file when a topic needs one. Only split an existing file when you would have to read unrelated code to change one thing. Size alone is not a reason: plain lists (`wardrobe.js`) and files with clear sections (`logic.js`) can be long. A split must not change behavior: run `npm test`, bump the build and check the preview.
- She plans to release in the app store, not as a plain web page: don't worry about browser-only concerns (keep the speech code swappable, see Voice).

## Product decisions

- **Names (decided build 252):** the app is **Fumufumu** (ふむふむ: "hmm, I see", said while nodding) and the mascot is **Fumu**, a pigeon (head bobs, eats anything). New players start as the pigeon (species `birdie`, skin `pigeon`, named Fumu; these are the `petProfile` defaults, older saves keep their own species; old saves named Nibble become Fumu), and the species list starts bird, cat, dog, mochi (`SPECIES` in `app-petsheet.js`); the mochi is shown as "Mochi". Internal names that must NOT change, because saved data and installs depend on them: the `nibble.v1`, `nibble.*` and `nibble-*` storage keys, the `nibble-vNN` cache names, `window.nibbleDesktop`, `NIBBLE_URL`, the installer id `com.laurmoe.nibble` and the `nibble-desktop` package name. The pigeon skin `pigeon` is the new design; the earlier one is `oldpigeon` ("Pigeon (old)"). A pet "nods" (`nod` in `SQUISH`) when you add an item, with a "fumu fumu~" line now and then.
- Free, usable, no ads. Monetization later via paid pet customization (the dressing room tests that idea; no payments yet).
- Deals/price data are dropped for now (store data is US-centric and not useful in Europe). Research is parked in `docs/research/competitors-and-deal-data.md`.
- Each person gets their own pet; only lists would be shared (not a household pet). All pet data stays in one object (`state.pet`, via `PetLogic.petProfile`) so it can sync per person. Keep it that way. A desktop companion and account sync are planned but not started: see `docs/design/desktop-companion-and-sync.md` (no AI chat, desktop awareness never reads window titles). Awareness has two levels the player picks in the desktop settings (Privacy: 1 more privacy, 2 normal): see `desktop/privacy.js`; every new thing that notices what the player does must be gated by it. Level 2 means the front program's file name (matched in the shell against `desktop/programs.js`, which is the only thing that may name a program to the page) and window positions, never titles: do not describe it as reading titles, and never send the page a program name that is not on the list (`programs.describe`). The page reacts in `app-desktop.js` (`onProgram`, `mayRemark`, `quietNow`; remarks run at the rate chosen in settings, `chatRate`, one for the usual case and one for games/full-screen, `inFull`; `moveOk` is the stand-still choice; per-game lines go in `GAME_LINES`). How much he talks on his own is `chatterRate` (`app-pet.js`; `applyChatter` in `app-desktop.js` picks the usual or the full-screen choice) and `idleQuiet` mutes `say` for a silent idle move; the stable (friends') build also shows update checking and restart in the right-click menu and the settings window, with `updateState` from `main.js`.
- No known app combines a list with a pet. Real rivals are shared-list apps (AnyList, Bring!, OurGroceries, Listonic); Finch, Otto and Habbie are pet habit apps.

## How the code is organised

Plain web app, no build step, no dependencies. `npm test` runs Node's built-in test runner on `tests/`, which load the same scripts the browser uses (the `app*.js` page scripts are only checked to parse, in `tests/syntax.test.js`).

- `index.html`, `styles.css`: UI. Bottom sheets are capped by `--sheet-h` (and `--sheet-h-s`) so Fumu stays in view above them. The look is cardboard (kraft board, taped paper labels, sticker buttons) with light and dark modes; its rules are at the end of `styles.css` under `html:root`. Fumu is an inline SVG animated with CSS. The pet buttons live in the `.dock` bottom bar (Pet, Room, Shop (placeholder, greyed out), Calendar, Profile; sticker colours are set by button id).
- `app*.js`: the UI code, split by topic. Plain scripts sharing one scope (no modules), loaded in the order in `index.html`; top-level code can only use things from files loaded before it. Read only the file you need:
  - `app.js` (first): `BUILD`, saved state, helpers, page elements, list rendering.

On a new browser the Send page has an "Owner? Turn on uploads" link (`#skOwnerLink`) that does what `?owner=1` does. The Upload button and the GitHub connection box are hidden for visitors (`body.skp-guest`, `.owner-only`): they show only in a browser that has a token saved or has been opened once with `sketch.html?owner=1` (`nibble-sketchpad-owner`); this only keeps the button out of the way, the real lock is that uploading needs her token. "Upload to Claude" puts `drawings/<kind>-<mode>-<time>.svg` (plus `.strokes.json`, and `.item.js` when an item name is given) on the **`drawings` branch** of the repo through the GitHub API with a fine-grained token she pastes in once (kept in her browser only); the branch keeps main (and its Pages deploy) untouched. When she says she uploaded something: read it with `get_file_contents` on `drawings/` at ref `drawings`, redraw it cleanly as game-style SVG (not the raw strokes) and compare it over the pet. Save SVG and Copy SVG are the fallbacks. It goes live with the rest of the site on a big push.
- `foods.js`: keyword to emoji dictionary. After adding emoji (here or in `tasks.js`), run `node tools/copy-emoji.js <openmoji package>/color/svg` (openmoji@17). The copy recolours the outlines to cocoa brown and softens every fill (`tools/emoji-style.js`: a little less saturated and lighter, for the pastel kraft look); change the look there and re-run the copy, never edit the files in `emoji/` by hand. In the list they are die-cut stickers (cream edge, thin cocoa line, soft shadow), drawn once per emoji on a canvas by `stickerize` in `app.js` (build 240). Never put a stack of CSS `drop-shadow` filters on every row: nine of them made Chrome drop to 25 fps on a long list and when sliding a row away (Firefox did not mind).

### Species and skins

- Species: birdie (the pigeon is the mascot), cat, dog (id `puppy`), mochi (shown as "Mochi" in the pet sheet; the id stays `mochi`), pig, bunny, cow, hamster, mouse, monkey, dragon, frog, hedgehog, axolotl (list in `app-petsheet.js`, parts drawn in `index.html` with `data-sp`). A species is a body (`pet.species`); a skin (`pet.skin`, `skins.js`) changes colours and parts on it. Prefer a skin over a new species when the new look is mostly colour on an existing body. Skin parts use `data-sk` (shared ones `data-sk="a b"`, matched with `~=`) and `data-skin` rules in `styles.css`.
- Skins on the frog, hedgehog and axolotl need `.pet[data-species=...][data-skin=...]` for colours, because those species' rules come later in `styles.css`. Gradients a skin uses live in the pet SVG's `<defs>`; `#bodyClip` (the body shape) stops markings at the edge (tabby stripes). Only the tabby and orange cat have stripes.
- Old saves: chick -> birdie, penguin -> birdie + penguin skin; removed skins (yak, Lionhead, tabby) fall back to the plain look; the flame point became the Siamese.
- Birds (`PetLogic.BIRDS`) get `.beaked` and no mouth; treat future birds the same. A beak never changes size (no scale on `.beak`): chewing and opening only move it with `translate`.
- Ears are `.ear-l`/`.ear-r` (`.ear-g`) groups behind the body; the cats' are `.kitty-ears`. The axolotl's gills are `.ear-g` too. Floppy ears (dog, floppy bunny) pivot at the top, upright ones at the bottom.
- All eye states live in `.eye-set`. Don't put `transform` on the eye groups: the blink animation overrides it. Eye parts carry `.eye-l`/`.eye-r` and are moved with the CSS `translate` property (every pet's eyes sit a little wider and lower than drawn; glasses are adjusted to match).
- The mouse has big round side-top ears, whiskers (`.whiskers`) and the bunny's buck-teeth smile. The monkey has side ears, a heart-shaped face mask (`.monkey-mask`, colour `--monkey-face`) and long feet with a thumb-like big toe (`.monkey-feet`, hidden by shoes); its only skin is the snow monkey (grey, red face). Neither has a tail.
- The dragon (id `dragon`) has small pink bat wings (`.ear-g` groups, so they jiggle with the ears; their bone lines are clipped to the wing by `#dragonWingL/R`) and stiff cream horns that never move (`.dragon-horn`, ring lines clipped by `#dragonHornL/R`) behind the body, a cream snout with nostrils, a belly plate with lines, leafy head tufts and a lower smile (`.smile-dragon`; its other mouths are moved down 3px). No tail. Keep belly and plate shapes inside the body outline.
- Animal faces (bunny, cat, dog, hamster, hedgehog, mouse, monkey): a nose (`.nose-round`, `.nose-cat`, `.nose-dark`, drawn after the mouths) and a :3 smile (`.smile-lip`, or `.smile-bunny` with buck teeth); set per species in `styles.css`.
- Each foot is its own group (`.foot-l`/`.foot-r`; shoes are split by `splitShoes` in `wardrobe.js`). Paws, hooves and bird toes are `.paw-part`, `.hoof-part`, `.bird-part`; which species shows which is set in `styles.css`. The frog keeps its own webs. Mouth items on birds are moved up to the beak (`.pet.beaked .outfit-mouth`; hay and leaf are held at its corner).
- Species and skin size: `--pet-size` on `.stage` (set with `.stage:has(#pet[data-species=...])` or `[data-skin=...]` in `styles.css`; so far only the munchkin cat is .8; mochi .8 and pig 1.2 were tried in build 169 and looked right, then she went back to full size) changes the main pet's box (`#pet` width and height), so the whole drawing scales with it without a CSS scale on the drawing. The speech bubble and the toy (`toyHome`, `toyBackHome`) keep clear of it. The dressing room preview and the small pictures keep one size. Check hats, the lamp and the bed when trying a size.
- Eye moves: `eyesDo('wide'|'squint')` scales the eye parts (classes `eyewide`/`eyesquint`); reactions pick one with `look`. `bellyJiggle` is a `SQUISH` wobble with a tummy pat.
- Food reactions: `REACTIONS` in `app-pet.js` by category, plus special ones from `REACTION_RULES`/`reactionOf` (no chocolate for any species but the mochi; chocolate, grown-up drinks and pet food go in the bag via `isBagged`).

### Features

- **Resting mood**: `PetLogic.restingMood` is the list mood, or asleep once put to bed tonight (`pet.dozing` holds that night; checking an item off clears it in `toggle`). `refreshBedtime` drops a left-over `dozing` unless a bedtime is showing or the app opens at a real night. Use `L.mood` for list-only checks such as "all done". Options (gear) are saved in `state.settings`, separate from the pet.
- **Walking** (`walkTo`/`walkPath` in `app-idle.js`): slides `#pet` with the CSS `translate` property (`--walk-x` on `.stage`, so the bubble follows). `walkBounds` keeps it from hiding behind the receipt or bag; eating and petting stop a walk; it returns to its cushion at bedtime. It only wanders when nothing is left to buy (`mayWander`); otherwise `walkHome` brings it back to the middle.
- **Backgrounds** (`BACKDROPS` in `app-backdrop.js`): SVG 400 x 160, cut at the sides on narrow screens, picked in the Room sheet (under the furniture) and kept on the device. Each `draw(night)` returns a day or night version (night 10 pm to 7 am via `petNow`, so the dev day/night switch works).
- **Toy** (`app-toy.js`): a ball on the floor (yarn for cats, tennis ball for dogs). Tap it and it bounces away and the pet chases it (`walkTo`, `walkWide`): dogs and birds fetch it back, cats bat it, the frog snatches it with its tongue (`tongueGrab`, the `#frogTongue` strip); a cat never catches a thrown toy in the air, it waits for it to land and then hunts it (`fling` skips `caught` for 'bat'), the rest pounce and hug it. It can be dragged and thrown (`fling`, with gravity and bounces; the pet catches it or fetches it). Only a game; nothing counts for goals. Hidden at bedtime. Its default place is on the right.
- **Voice** (`app-voice.js`, `L.splitSpoken`): the mic button `#micBtn` listens once, shows the words in the box, then adds each thing said (the shopping list splits on commas and "and"/"en"; the to-do list only on commas and "then"). All speech goes through the `Voice` object (`supported`, `listen`), which uses the browser's SpeechRecognition: for the store app, swap that one object for the phone's native recognition. Language is Auto, English or Nederlands (Options, kept on the device). The manifest shortcut "Add by voice" opens `./?voice=1`, which starts listening; if the browser refuses without a tap, the mic pulses and Fumu says to tap it.
- **Aisles** (`L.AISLES`, `aisleOf`, `groupByAisle`, `aisleNodes` in `app.js`): the shopping list is shown grouped under small labels (fruit & veg, bakery, meat & fish, dairy & eggs, pantry, drinks, treats, household, health, other) in shop-walking order. It is display only: the list's own order is untouched. An item's aisle comes from its emoji's food category (beans, nuts and seeds count as pantry). Option `aisles` (on by default) turns it off.
- **Options**: `time24` (14:30 or 2:30 PM), quiet mode, vibration, goal toasts, fair-play tips, appearance, voice language; the Developer tools sheet lives in Options.

#### To-do list (`app-todo.js`, `tasks.js`)

- Tapping the title (`#brand`) swaps the shopping list and the to-do list. The list on show is always `state.items`; the other waits in `state.stash`; `state.mode` ('shop' or 'todo') says which is which, so the rest of the code works on whichever is showing (`isTodo()`). `L.emojiFor`/`createItem` take the mode; `Tasks.match` gives emoji and a kind (chore, call, health, money...).
- Ticking a task runs `doTask` instead of `eat` (the emoji flies over the pet and gets a check-mark stamp; reactions come from `TASK_REACTIONS` by kind plus `TASK_RULES` by words); `undoTask` replaces the spit. No receipt, cart or bag. Nothing counts for goals, tastes, trips or the Top 10 (`toggle` skips them). Suggestions are off and daydreams are about the tasks. A treat is still eaten. The emoji picker shows task emoji.
- Tasks can have `due` (YYYY-MM-DD), `time` (HH:MM) and `repeat` (`PetLogic.REPEATS`). Tapping a task's words opens `#taskSheet`; rows show a `.due-tag` (`dueInfo`; undated tasks show a dashed "+ date/time"); later days get `.later` (a soft tint), late ones `.late` (a very gentle shake now and then). Open tasks are kept in order by `sortByDue`: late, today, undated, then later days. Ticking a repeating task puts a copy back with `nextDue` (`repeatTask`; un-ticking removes it via `item.spawned`). Fumu mentions due tasks at start and now and then (`dueNag`; a badge on the title counts them while the shopping list shows), announces a task's time once when it comes (`timeCheck`, while the app is open), and ticking a timed task early asks first (`warnIfEarly`, `#earlySheet`).
- Clipboard: Fumu holds `#clipboard` in his left hand (drawn inside the `.arm-l` group so it moves with the arm; the arm's pivot is fixed in CSS because the clipboard would enlarge its box; the left arm keeps its raised holding pose whatever the face does; only the main `#pet` shows it). Its ticks follow progress (`updateTodoExtras`). The arm tilts with `transform` and sways with the `rotate` property. The `desk` pose (`deskOn`/`deskOff`; the clipboard turns over to `.cb-back`, class `flipped`) brings both paws and a prop (`.pencil` or `.magnifier`, drawn in the right arm, shown by `data-prop`) to the middle for `writeOnClipboard` (when a task is added), `inspectList` (the glass goes to his right eye; `.mg-eye` shows it enlarged, as open, sparkling, happy or closed like his own eye) and `lookOverList` (`TODO_MOVES`, picked by `idleMove` about half the time on the to-do list).
- The Calendar (`#calBtn`) is in the bottom bar on both lists (plans live in the to-do list, kept in `state.stash` while the shopping list shows: `planList`); Goals and the stamp book open from the Profile sheet. The calendar (`app-calendar.js`, `L.monthGrid`, `tasksOn`) shows a month, Monday first, with dots for plans; a plan is just a task with a `due` day (a birthday gets `repeat: 'yearly'`, switched on when the text says birthday), so it also appears in the to-do list once it is within 10 days (`L.isFarOff`, `PLAN_AHEAD_DAYS`; further away it only shows in the calendar, with a `#farNote` under the list). The month and year are drop-down menus. The stamp book (`app-stamps.js`, `pet.stamps` by task kind, `L.addStamp`/`stampTotal`) gets +1 when a task is ticked and -1 when un-ticked (`toggle`); rings get fancier at 1, 10 and 50. No streaks. Ticks made before build 160 aren't counted.
- A task ticked while he sleeps wakes him only for a happy word (he stays `dozing` and goes back to sleep). `sampleTodos` fills the dev tool's sample items in this mode.

#### Bedtime (`app-bedtime.js`)

- At night (`bedtimeNow`: night, unless you are in the middle of shopping, `shoppingNow`: something on the shopping list was ticked in the last 30 minutes and more is still to buy; waiting items and open tasks never keep him up), a pink pendant lamp hangs top right and lights the room (`.lamp-light`). The lamp hangs all night, even while shopping; switching it off then brings the bed so you can tuck him in (`night-lamp` is the lit lamp without the bed). It swings and tugs its own cord until it is off (the cord moves via the registered `--pull` property).
- Bedtime: the cushion becomes a round pet bed (`.pet-bed` rim behind, `.bed-front` bolster in front); the receipt, bag and toy are put away; the speech bubble sits on the left, clear of the lamp. Crickets chirp and an owl hoots.
- Night alone doesn't make him sleep: he stays awake and tired (`.pet.tired`, half-lidded eyes via `.tired-lid` inside `.pupils`; tired blinks, wide eyes and squints have their own keyframes; most idle moves are sleepy ones, `night: true` in `IDLE_MOVES`) and hints now and then (`bedHint`) until you switch the lamp off (tug the cord down; a plain tap only dips the bead) and tap him to tuck him in (`.pet.tucked` shows the `.blanket`, a patchwork quilt in the pet SVG, under the arms), in either order. Then `fallAsleep` sets `pet.dozing` and he snores.
- Asleep: switching the lamp on makes him grumpy; a tap or stroke gives a goodnight kiss (`kissGoodnight`); adding an item only gets a sleep-mumble; checking one off wakes him with a start (`wakeForSnack`) before he eats, and a treat wakes him briefly. Up at night, happy moments come out happy but tired (`isTired`, `tiredFace`, `tiredMove`, `TIRED_YUM` in `app-pet.js`).
- Bedtime starts fresh (lamp on, not tucked in, awake) whenever it begins, ends or he wakes while the app is open, including via the dev day/night switch; reopening keeps tonight's state (kept on the device per night, `PetLogic.nightOf`). In the morning he wakes with a stretch.
- Teddy: `TEDDY` is drawn into `.teddy-hug` in the pet SVG, before the arms, and sits beside him in the bed (`.has-teddy`). Falling asleep (on the to-do list he first puts the clipboard away: `.stowing`), the right paw reaches out (`grab` arms) and paw and teddy slide back together (`.pet.hugging`) so it ends tilted under the paw against his cheek; waking slides it back out. This is the build 139 version; a separate `#bedTeddy` element (builds 146-149) was dropped. The teddy can't go inside the arm group (arms turn round their own bounding box). Toy, lamp, bed, quilt, clipboard and teddy outlines use `--prop-ink`, Fumu's own dark brown #5b4239 in light and dark mode (the lamp, bed and quilt used a lighter brown until build 235).

## Lessons learned

- Speed: every row on the page costs frame time all the time (the pet's animations make the page redraw constantly), so the Bought list only draws its latest `DONE_SHOWN` rows (`app.js`). Don't add things that grow without limit to the page; cap what is drawn. A leak check (nodes, listeners, heap over many actions) was clean in build 237. Measure with Playwright: `Performance.getMetrics` (TaskDuration, LayoutCount) and a trace (`devtools.timeline`: Layerize, UpdateLayoutTree). `contain: layout` on `.stage` would help but breaks its fixed-position bubble.

- There are no scroll bars anywhere (sheets and the page): she dislikes them. `app-fade.js` fades the bottom edge of a scrolling menu (`.fade-b`, listed in `FADE_SELECTORS`) and of the page (`.page-fade`) while there is more to see; add any new scrolling menu to that list. Don't add `scrollbar-width: thin` or similar.
- Squash and stretch is drawn by `svgSquish` in `app-pet.js` (steps in `SQUISH`, played by `pulse`, plus `softSettle` in `app-idle.js`; `settle` is a different thing, it resets the face): it sets an SVG `transform` on `.pet-body` each frame. Never scale or rotate the pet with CSS: a CSS scale on `.squash` left a hairline across the face on her phone. `.squash` and `.pet-svg` moves only translate (a test checks `.squash`). Keep squashes at about 15% or less. The boogie dance and the rock/roly/wiggle tilts still use CSS scale or rotate on `.pet-svg`; move them to `svgSquish` if a seam shows. The seam is a Firefox drawing bug (not in Chrome), so judge animations in Chrome and Safari; a Firefox-only seam is acceptable.
- Keep shoes about the size of the original boots; oversized shoes looked awkward to her.
- The mochi hair twist: the fill covers the outline and the line ends on it, with the skin path starting at the bottom, so there is no seam.
- Test on a phone-sized viewport; she reports visual glitches that desktop hides.
