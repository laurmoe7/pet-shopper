# Pet Shopper (pet name: Nibble)

A grocery list with a tamagotchi-like pet that "eats" items as you check them off and gets happy. Owner: Lauren (GitHub laurmoe7), based in Europe. Private project. See `README.md` for the feature list and `docs/` for research and the pet/core-loop design.

## How to work with Lauren

- She wants honest, unflattering feedback. Don't flatter; say when something looks bad or is a weak idea.
- Priority is cute and appealing. Style is kawaii, inspired by Chiikawa but original (don't copy characters). Keep all pet species.
- She tests on her phone and reports by build number (shown in Options, `BUILD` in `app.js`). Always bump the build when you change app files.
- Changes go live by pushing to `main` (no pull request). When she says "big push" (she used to say "ship it"), run `npm test`, then push to `main`; the Pages workflow tests and deploys. Do this only when she asks, and check the preview with her first.
- Add to `CHANGELOG.md` for each build you ship, kept simple: a heading per build and one short line per change (a few words, no explanations or technical detail).
- She wants people to use the list legitimately, not game it for unlocks (hence the fair-play rules).

- Nothing requires an unlock for now: `FreeUnlocks.all` in `achievements.js` opens every species, skin, hat and personality. New things should not need unlocks either; goals still count progress and set `all` to false to bring unlocking back (the unlock rules and tests are kept). Skin parts that are shared between skins use `data-sk="skin1 skin2"` (matched with `~=`).
- Keep files focused. Put new code in the `app-*.js` file for its topic, and start a new file when a topic needs one. Only split an existing file when I would have to read through unrelated code to change one thing, as with the old single `app.js`. Size alone is not a reason: a plain list like `wardrobe.js`, or a file with clear sections like `logic.js`, is fine long because it can be searched and read in parts. A split must not change behavior: run `npm test`, bump the build and check the preview.

## Product decisions

- Free, usable, no ads. Monetization later via paid pet customization. The dressing room is currently a test of that idea; no payments yet.
- Deals/price data are dropped for now (store data is US-centric and not useful in Europe). Research is parked in `docs/research/competitors-and-deal-data.md`.
- A shared household pet is planned later, so all pet data stays in one object (`state.pet`, via `PetLogic.petProfile`). Keep it that way.
- No known app combines a list with a pet. Real rivals are shared-list apps (AnyList, Bring!, OurGroceries, Listonic); Finch, Otto and Habbie are pet habit apps.

## How the code is organised

Plain web app, no build step, no dependencies. `npm test` runs Node's built-in test runner on `tests/`, which load the same scripts the browser uses (the `app*.js` page scripts are only checked to parse, in `tests/syntax.test.js`).

- `index.html`, `styles.css`: UI. The look is cardboard (kraft board, taped paper labels, sticker buttons), with light and dark modes; its rules are at the end of `styles.css` under `html:root` (the old pink look was removed in build 103). Nibble is an inline SVG animated with CSS. The main pet buttons live in the `.dock` bottom bar (ids `dressBtn`, `roomBtn`, `treatBtn`, `favBtn`, `goalsBtn`, `editPetBtn`).
- `app*.js`: the UI code, split by topic. They are plain scripts sharing one scope (no modules), loaded in the order in `index.html`. Read only the file you need:
  - `app.js` (comes first): `BUILD`, saved state, helpers, page elements, list rendering.
  - `app-pet.js`: Nibble's faces, speech, flying food, crumbs.
  - `app-actions.js`: sound and haptics, the eating queue, list actions, emoji picker.
  - `app-petsheet.js`: edit pet. `app-dress.js`: dressing room. `app-room.js`: room furniture. `app-goals.js`: goals and unlocks.
  - `app-todo.js`: the to-do list (see below).
  - `app-events.js`: adding items, taps and long-presses. `app-personality.js`: personalities and suggestions.
  - `app-favourites.js`: the Top 10 sheet (medals, #1 pedestal). `app-petting.js`: stroking Nibble for a purr and hearts. `app-treats.js`: the Treats sheet (pick 3 free snacks a day; they count for goals and tastes but never the Top 10).
  - `app-voice.js`: adding by voice (see below). `app-options.js`: Options and Developer tools. `app-backdrop.js`: backgrounds behind the pet. `app-idle.js`: daydreams, idle moves, walking, eye following. `app-toy.js`: the toy to throw. `app-bedtime.js`: tucking in, the lamp. `app-start.js`: startup, loads last.
  - A new `app-*.js` file must be added to `index.html`, `SHELL` in `sw.js` and `SCRIPTS` in `tools/build-preview.js`. Top-level code runs as the file loads, so it can only use things from files loaded before it.
- `logic.js` (`PetLogic`): rules with no page code (item order, mood, saved state, achievement counting, unlocks, favourites tally (`pet.favourites`, same fair-play rules as goals), voice lines, `OUTFIT_SLOTS`, `BIRDS`, dev helpers like `unlockAll`/`skipDays`). Keep logic here so it is testable.
- `wardrobe.js`: dressing-room items drawn as SVG. Outfit slots are `hat`, `body` (clothes such as hoodies; a hood and a hat take each other off), `face`, `mouth`, `neck`, `feet` (`PetLogic.OUTFIT_SLOTS`); each has its own layer (`.outfit-neck` under face, moved to `.outfit-neck-over` above clothes when clothes are worn, `.outfit-mouth` in front of the face, `.outfit-feet` in front of body). Renamed or removed items are mapped in `parseOutfit` in `logic.js`. Each item has hover `lines`; a `snug` flag hides the hair twist/tuft (bandana, headphones, helmet). Add cosmetics here.
- `achievements.js`: goals, daily caps per calendar day, what each unlocks. Add goals here.
- `personalities.js`: personalities, tastes, `voice`. Foodie is free; the others are earned via `pet.tastes`.
- `decor.js`: room furniture (draggable, stored in `pet.room`). The rug is drawn first.
- `foods.js`: keyword to emoji dictionary. After adding emoji, regenerate with `node tools/copy-emoji.js <openmoji package>/color/svg` (openmoji@17).
- `sounds.js`: Web Audio sounds with random pitch and variants.
- The to-do list (`app-todo.js`, `tasks.js`): tapping the title (`#brand`) swaps the shopping list and the to-do list. The list on show is always `state.items`; the other waits in `state.stash`, and `state.mode` ('shop' or 'todo') says which is which, so the rest of the code works on whichever is showing. `tasks.js` (`Tasks.match`, kinds like chore, call, health, money) gives to-do emoji, and `L.emojiFor`/`createItem` take the mode. In to-do mode: ticking a task runs `doTask` (not `eat`: the emoji flies over the pet's head, gets a check-mark stamp, and reactions come from `TASK_REACTIONS` by kind plus `TASK_RULES` by words), `undoTask` replaces the spit, there is no receipt, cart or bag, and nothing counts for goals, tastes, trips or the Top 10 (`toggle` skips them); suggestions are off and daydreams are about the tasks. Tasks can have `due` (YYYY-MM-DD) and `repeat` (`PetLogic.REPEATS`): tapping a task's words opens `#taskSheet` (chips and a date input), rows show a `.due-tag` (`dueInfo`), open tasks are kept in due order (`sortByDue`), ticking a repeating task puts a copy back with `nextDue` (`repeatTask`; un-ticking removes it again via `item.spawned`), Nibble mentions due tasks at start and now and then (`dueNag`; a badge on the title counts them while the shopping list shows), and he holds a `#clipboard` in his left hand (drawn inside the `.arm-l` group, so it moves with the arm; the arm's pivot is fixed in CSS because the clipboard would enlarge its box; the left arm keeps its raised holding pose whatever the face does, the right arm stays free; only the main `#pet` shows it, not the dress-up or pet-sheet copies) whose ticks follow progress (`updateTodoExtras`); the left arm is tilted with `transform` and sways with the `rotate` property; the `desk` pose (`deskOn`/`deskOff`; the clipboard turns over to its `.cb-back` so the paper faces him, class `flipped`) brings both paws and a prop (chubby `.pencil` or `.magnifier`, drawn in the right arm, shown by `data-prop`) to the middle for `writeOnClipboard` (when a task is added), `inspectList` (the glass goes up to his right eye and `.mg-eye` shows it enlarged) and `lookOverList` (`TODO_MOVES`, picked by `idleMove` about half the time on the to-do list); a task can also have a `time` (HH:MM) and `timeCheck` makes him announce it once when it comes, while the app is open; ticking a timed task before its time asks first (`warnIfEarly`, `#earlySheet`). A task ticked while it sleeps wakes it only for a happy word (it stays `dozing`, then goes back to sleep). The `time24` option picks 14:30 or 2:30 PM (`fmtTime`; the sheet uses hour, minute and AM/PM selects). Tasks due after today get `.later` (a soft tint). Undated tasks show a dashed "+ date/time" tag. Bedtime only looks at the shopping list. A treat still gets eaten. The emoji picker shows task emoji. Run `tools/copy-emoji.js` after adding any to `tasks.js`.
- Voice (`app-voice.js`, `L.splitSpoken`): a mic button (`#micBtn`) in the Add bar listens once, shows the words in the box while it listens, then adds each thing said ("milk, eggs and bread" is three items; the to-do list only splits on commas and "then"). All speech goes through the `Voice` object (`supported`, `listen`), which uses the browser's SpeechRecognition; Lauren plans a store app, so swap that one object for the phone's native recognition there. The language is Auto (the phone's), English or Nederlands (Options, kept on the device). The manifest shortcut "Add by voice" opens `./?voice=1`, which starts listening at once (if the browser refuses without a tap, the mic pulses and Nibble says to tap it).
- Birds (the birdie, `PetLogic.BIRDS`) get `.beaked` and no mouth; treat future birds the same. Ears live in `.ear-l`/`.ear-r` groups.
- Species: mochi (shown as "Nibble" in the pet sheet; the id stays `mochi`), pig, cat, dog, bunny, birdie, cow, hamster, frog, hedgehog, axolotl (list in `app-petsheet.js`, parts drawn in `index.html` with `data-sp`). All eye states live in `.eye-set`, so a species can move the eyes as one. Don't put `transform` on the eye groups themselves: the blink animation overrides it.
- Species and skins: a species is a body (`pet.species`); a skin (`pet.skin`, list in `skins.js`) changes colours and parts on that body. The axolotl's gills are `.ear-g` groups (a test counts `.gill-fill` as its ears). Sheets have no Done button: a `.sheet-grab` bar (added in `app.js`) closes them. Skins so far: birdie (original, penguin, parrot, kiwi, pigeon, chicken), mochi (strawberry, chocolate, taro), cat (original is a grey tabby; black cat, calico, orange, munchkin, ragdoll, Scottish fold, Siamese; only the tabby and the orange cat have stripes), dog (chihuahua, Pomeranian, golden retriever, pink shiba, French bulldog, German shepherd, cairn terrier), frog (poison dart frog, toad), cow (chocolate milk, Highland cattle, strawberry cow), pig (dirty piggy, boar, potbelly), bunny (floppy ears, Dutch, Himalayan), hamster (white, long-haired black), hedgehog (fast, Brandt's), axolotl (rainbow). Skins on the frog, hedgehog and axolotl need `.pet[data-species=...][data-skin=...]` for their colours, because those species' colour rules come later in styles.css. Gradients a skin uses (rainbow axolotl, pigeon) live in the pet SVG's `<defs>`, with `#bodyClip` (the body shape) for markings that must stop at the edge, like the tabby stripes. Ears go behind the body (the cats' are `.kitty-ears`, which a skin can swap). A skin is drawn with `data-skin` rules and `data-sk` parts in `styles.css`/`index.html`; a species' own parts use `data-sp`. Old saves load with chick -> birdie and penguin -> birdie + penguin skin; removed skins (yak, Lionhead, tabby) fall back to the plain look, and the flame point became the Siamese. Prefer a skin over a new species when the new look is mostly colour on an existing body.
- Each foot is its own group (`.foot-l`/`.foot-r` in `index.html`; shoes are split into `.shoe-l`/`.shoe-r` by `splitShoes` in `wardrobe.js`), animated in the feet section of `styles.css`.
- Food reactions: `REACTIONS` in `app-pet.js` by category, plus special ones picked by `REACTION_RULES`/`reactionOf` (no chocolate for any species but the mochi, sour, crunchy, cold, coffee, grown-up drinks and pet food; chocolate, grown-up drinks and pet food go in the bag via `isBagged`).
- Animal faces (bunny, cat, dog, hamster, hedgehog): a nose (`.nose-round`, `.nose-cat`, `.nose-dark`, drawn after the mouths so the :3 lines never cover it), a :3 smile (`.smile-lip`, or `.smile-bunny` with buck teeth) Every pet's eyes sit a little wider and lower than drawn (eye parts carry `.eye-l`/`.eye-r`, moved with the CSS `translate` property so blinks and sparkles still work), and glasses (`.outfit-face`) are widened and lowered to match. Noses and mouths are set per species in styles.css.
- Birds' hands are three tiny wing-tip ellipses (`.bird-hand`, coloured by the arm rule). Paws, hooves and bird toes are `.paw-part`, `.hoof-part` and `.bird-part` in `index.html`; which species shows which is set in `styles.css` (not `data-sp`). The frog keeps its own webs.
- Walking: `walkTo`/`walkPath` in `app-idle.js` slide `#pet` with the CSS `translate` property (`--walk-x` on `.stage`, so the bubble and daydream follow). `walkBounds` keeps it from hiding behind the receipt or bag; eating and petting stop a walk (`stopWalk`), and it goes back to its cushion at bedtime. It only wanders when nothing is left to buy (`mayWander`); with items on the list `walkHome` brings it back to the middle. Turning to face the way it walks was tried in build 113 and dropped: the front-facing pet looks the same mirrored.
- Backgrounds behind the pet: `BACKDROPS` in `app-backdrop.js` (SVG, 400 x 160, cut at the sides on narrow screens), picked in Options and kept on the device like Appearance. Each `draw(night)` returns the day or night version (night from 10 pm to 7 am, via `petNow`, so the dev day/night switch works); `.bd-dark` pictures aren't dimmed in dark mode.
- The toy (`app-toy.js`): a ball on the floor (yarn for the cat, a tennis ball for the dog, set by species in styles.css). Tap it and it bounces away and the pet runs after it (`walkTo(x, pace)`, with `walkWide` giving it more floor while it plays): dogs and birds fetch it back in their mouth, cats bat it about first, the frog snatches it with its tongue (`tongueGrab`: the `#frogTongue` strip stretched from the mouth to the toy, which comes back stuck to it, then it fetches it back; it catches thrown toys from further away), the rest pounce and hug it. It can also be grabbed and thrown (`fling`: drag it and let go; it flies at the throw's speed with gravity, bounces off the sides, top and floor of the stage, and the pet runs under it to catch it, `caught`, or gets it off the floor, `landed`/`getIt`). Only a game: nothing counts for goals. Hidden at bedtime.
- Bedtime (`app-bedtime.js`): at night, unless you are in the middle of shopping (`shoppingNow`: something on the shopping list was ticked in the last 30 minutes and more is still to buy; items waiting on the list and open tasks never keep it up) (`bedtimeNow`), a pink pendant lamp hangs top right (all night, even while shopping: switching it off then brings the bed so you can tuck it in; `night-lamp` is the lit lamp without the bed), lights the room around it (`.lamp-light`), and swings and tugs its own cord now and then until it is off (the cord moves via the registered `--pull` property); the cushion becomes a round pink pet bed (`.pet-bed` rim behind the pet, `.bed-front` bolster in front, so it lies in it), and the receipt, bag and toy are put away. Night alone doesn't make it sleep: it stays awake and tired (`.pet.tired` half-lidded eyes, `.tired-lid` inside `.pupils` so the lids move with the eyes; tired blinks, wide eyes and squints have their own keyframes that start and end half-closed, and the blink drops the lid onto each eye rather than squeezing the eye set round its middle; most idle moves are sleepy ones, `night: true` in `IDLE_MOVES`: yawning, rubbing its eyes with the `eyerub` arms, nodding off, heavy blinks) and hints now and then (`bedHint`) until you switch the lamp off (tug the cord down, `click` sound; a plain tap only dips the bead; Enter/Space work for keyboards) and tap it to tuck it in (`.pet.tucked` shows the `.blanket`, a patchwork quilt in the pet SVG with its fabrics as `<pattern>`s in the defs, under the arms so the paws rest on it), in either order. Then `fallAsleep` sets `pet.dozing` and it snores every few seconds (`snore`/`snorebig`, a breath and z's). Asleep: switching the lamp back on makes it grumpy (a squint), a tap or a stroke gives it a goodnight kiss (`kissGoodnight`: a smooch sound, a kiss mark on its forehead, a sleepy smile and blush), adding an item only gets a sleep-mumble, and checking one off wakes it with a quick start (`wakeForSnack`) before it eats. Crickets chirp and an owl hoots at bedtime (the first hoot a few seconds in). The speech bubble sits on the left at bedtime, clear of the lamp. Bedtime starts fresh (lamp on, not tucked in, awake) each time it begins, ends or the pet wakes while the app is open, including via the dev day/night switch; reopening the app keeps tonight's (the lamp and quilt are kept on the device per night, `PetLogic.nightOf`). In the morning it wakes with a stretch. A teddy bear (`TEDDY` in `app-bedtime.js`, drawn into `.teddy-hug` in the pet SVG, before the arms) sits in the bed beside the pet at bedtime (`.has-teddy`); falling asleep (on the to-do list he first puts the clipboard away: `.stowing`), the right paw reaches out to it (`grab` arms) and paw and teddy slide back together with the same timing (`.pet.hugging`), so it ends tilted under the paw against his cheek; waking slides it back out. This is the build 139 version; builds 146-149 tried a separate `#bedTeddy` on the bed and were dropped. (The teddy can't go inside the arm group: the arms turn round their own bounding box.) The toy, lamp, bed, quilt and teddy outlines use `--prop-ink`, the same dark brown in light and dark mode. Up at night, happy moments come out happy but tired (`isTired`, `tiredFace`, `tiredMove`, `TIRED_YUM` in `app-pet.js`): eating, treats, the all-done party and closing the dressing room; a treat given while it sleeps wakes it briefly (`wakeForSnack`), then it goes back to sleep.
- Eye moves: `eyesDo('wide'|'squint')` in `app-pet.js` scales each eye part with the CSS `scale` property (classes `eyewide`/`eyesquint`); reactions pick one with a `look` field. `bellyJiggle` is a `SQUISH` wobble with a tummy pat and its own sound.
- The pet's resting mood is `PetLogic.restingMood`: the list mood, or asleep once it has been put to bed tonight (`pet.dozing` holds that night, set by `fallAsleep`; it stays asleep when things are added, and checking an item off clears it in `toggle`). `refreshBedtime` drops a left-over `dozing` unless a bedtime is already showing or the app opens at a real night, so a dev-tool night can't leave it asleep. Use `L.mood` for list-only checks such as "all done".
- Options (gear) are saved in `state.settings`, separate from the pet. Developer tools sheet lives in Options.

### Service worker and builds

`sw.js` caches the app shell. Whenever you change any cached file: bump `CACHE` in `sw.js` (`nibble-vNN`) and `BUILD` in `app.js` to the same number (a test checks they match), and add any new script to `SHELL`.

### Phone preview

Lauren previews on her phone via a single-file build (styles and scripts inlined, emoji published alongside) published as a claude.ai artifact, and the repo is also served by GitHub Pages under `/pet-shopper/`. `npm run preview` builds `preview/index.html` (styles and scripts inlined) plus `preview/emoji/`; `npm run preview:bump` raises `BUILD` and `CACHE` by one first. Publish `preview/index.html` to the existing artifact URL; emoji only need uploading on the first publish, later publishes keep them.

## Lessons learned

- Squash and stretch is drawn by `svgSquish` in `app-pet.js` (steps in `SQUISH`, played by `pulse` for chomp, spit, stretch, pat, hop, hopsmall, hophop, plus `softSettle` in `app-idle.js`; `settle` in `app-pet.js` is a different thing, it resets the face): it sets an SVG `transform` on `.pet-body` each frame, so the phone redraws the shapes. Never scale or rotate the pet with CSS: a CSS scale on `.squash` left a hairline across the face on her phone (found in build 72, fixed this way in builds 81-84). `.squash` and `.pet-svg` moves only translate (a test checks `.squash`). Keep squashes at about 15% or less: the 30-40% squashes of build 81 still showed a seam. The boogie dance and the rock/roly/wiggle tilts still use CSS scale or rotate on `.pet-svg`; move them to `svgSquish` if a seam shows there. The seam is a Firefox (Gecko) drawing bug: in build 84 it still showed in Firefox on her Pixel but not in Chrome. A Play Store or App Store app would use the Chrome or Safari engine, so judge animations in Chrome (she tests a Chrome-installed copy) and Safari; a Firefox-only seam is acceptable.
- Keep shoes about the size of the original boots; the first oversized shoes looked awkward to her.
- The mochi hair twist: fill covers the outline and the line ends on it, with the skin path starting at the bottom, so there is no seam.
- Test on a phone-sized viewport; she reports visual glitches that desktop hides.
